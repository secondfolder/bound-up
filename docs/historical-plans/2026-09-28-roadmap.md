# Roadmap: a public "growing tree" at /roadmap, plus a landing-page teaser

## Context

We want to show people what Bound Up plans to build, as a tech tree loosely
inspired by [Up's Tree](https://up.com.au/tree/). The roadmap items come from the
rough notes in `.local/roadmap.md`, cleaned up into a JSON file. `/roadmap` is
a new public page. The landing page `/` gets a section with featured upcoming
items, recently shipped ones, and a link to the full roadmap. Both have to work
well on a phone.

Decisions made with the user:

- **Placement:** `/roadmap` lives under `(public)`, so it is reachable signed in
  or out. The teaser goes on the landing page `/`, not on `/home`.
- **Design:** a "growing tree": semantic HTML with drawn connectors, and no
  graph library.
- **Depth:** three levels. Branch (category), then leaf (feature), then twig
  (sub-feature). Each level has its own status.

### Research summary (why this design)

- **Up's Tree** is one hand-illustrated SVG with jQuery drag, pinch and zoom.
  Tapping a leaf opens a popup card, and there are side panels for "released"
  and "calendar". Its data is a flat `cards` array of
  `{id, title, status, desc, section}` with the statuses shipped, in progress,
  planned, exploring and pruned. We keep its data shape and status vocabulary,
  but not the illustrated SVG: every new item would need new artwork.
- **Svelte Flow (@xyflow/svelte) with dagre or ELK:** a real pan/zoom graph
  that handles dependency edges. It adds about 150KB, reads as a node editor,
  and pan-and-pinch is clumsy on a phone. Rejected.
- **d3-hierarchy with a panzoom library:** gives the most organic tree, but it
  is all SVG, so accessibility, labels on mobile and SSR all get harder.
  Rejected.
- **Chosen: a scroll-native tree.** The page scroll does the navigation, so
  there is nothing to pan or pinch. It is nested `<ol>`/`<ul>` markup, so it
  renders on the server and works with a screen reader, and it adds no
  dependencies. The connectors are CSS pseudo-elements with rounded corners;
  that is the classic CSS-tree technique. They need no JS measuring or
  ResizeObserver, so they cannot drift while the page hydrates. A computed SVG
  layer stays possible later if we want curvier boughs. Dependency links
  between branches are listed in the item's details rather than drawn as edges
  across the tree, which would clutter it.

## Data: `src/lib/roadmap/roadmap.json` + `src/lib/roadmap/index.ts`

`index.ts` is alias-free, has no server imports and is imported directly by
components. It validates the JSON with Zod when the module loads, so a bad edit
fails `npm test`, `check` and the dev server loudly. It exports the types and
these selectors:

```ts
type RoadmapStatus = 'shipped' | 'in-progress' | 'planned' | 'exploring';
interface RoadmapItem {           // leaf and twig share the shape
  id: string;                     // kebab-case, unique across the whole file (used as #hash)
  title: string;
  summary: string;                // one user-facing sentence
  status: RoadmapStatus;
  icon?: string;                  // Font Awesome name for <wa-icon>
  notes?: string[];               // short bullets shown in the detail drawer
  featured?: boolean;             // candidate for the landing "Coming up" row
  shippedOn?: string;             // YYYY-MM-DD; required iff status === 'shipped'
  dependsOn?: string[];           // ids of other items
  children?: RoadmapItem[];       // twigs (leaves only; twigs have none)
}
interface RoadmapBranch { id; title; summary; icon; items: RoadmapItem[] }
```

The Zod schema refines these rules: ids are unique; every `dependsOn` points at
an existing id; there are no dependency cycles; `shippedOn` is present exactly
when the status is `shipped`; `children` only appear on leaves.

Selectors:

- `allItems()` flattens the tree and returns each item with its branch and
  parent.
- `findItem(id)`.
- `featuredUpcoming(limit)`: items with `featured` whose status is not
  `shipped`, in file order.
- `recentlyShipped(limit)`: shipped items sorted by `shippedOn` descending,
  then by id.
- `statusCounts()`: the numbers for the legend.

## UI

### `/roadmap`: `src/routes/(public)/roadmap/+page.svelte` (no load; imports the data)

- **Header:** an `h1` "Roadmap" and one sentence of intro. The status legend
  doubles as a filter: native `<button aria-pressed>` toggles, with a comment
  explaining why they are native (`wa-button` does not forward
  `aria-pressed`). Filtering dims the items that don't match rather than
  removing them, so the tree's shape holds steady. The page has a back link to
  `/` whose accessible name is distinct, since the (public) group has no header
  and each page links onward itself. When the visitor is logged out, a link
  says "Sign up to Bound Up".
- **`src/lib/components/roadmap/RoadmapTree.svelte`:**
  - The markup is an `<ol class="trunk">` of branches. Each branch is an
    `<li class="bough">` holding a branch node (icon and title) and a
    `<ul class="leaves">`. Each leaf `<li>` holds a `RoadmapNode` and a nested
    `<ul class="twigs">`.
  - The trunk is a vertical rule. A bough is a rounded elbow connector from the
    trunk to the branch node. Leaves and twigs hang off `border-inline-start`
    rules with curved `::before` elbows.
  - A ground line at the foot of the trunk says "Planted Sept 2026" and shows
    the shipped count.
  - **Mobile (default):** the trunk runs down the left gutter and every branch
    grows to the right. There must be no horizontal scroll at 360px.
  - **Desktop (`min-width: 720px`):** the trunk is centred, using grid columns
    `1fr auto 1fr`. Boughs alternate left and right, and the left-hand ones are
    mirrored with logical properties and `text-align: end`. The (public)
    container's 800px is wide enough for this, so the layout wrapper doesn't
    change.
  - All colours come from existing `--wa-color-*` and `--accent-*` tokens (see
    `src/lib/theme.css`). If a new status colour is needed, it becomes a token
    in `theme.css` first.
- **`RoadmapNode.svelte`:** the node is an `<a href="#{id}" id={id}>`, so each
  one is deep-linkable, is a real link without JS, and scrolls into view.
  Status is shown by shape and by a text label, never by colour alone:
  - **shipped:** a solid amber disc with a check;
  - **in progress:** a half-filled ring that pulses gently, with the pulse off
    under `prefers-reduced-motion`;
  - **planned:** an outlined ring;
  - **exploring:** a dashed ring with a "?".

  Next to the node sit a `wa-icon` (with a label, or `aria-hidden` when it is
  decorative next to the title), the title, and a visually-hidden status word.
  The one-line summary is shown on desktop and clamped on mobile.
- **`RoadmapDetails.svelte` in a `wa-drawer`:** a `$derived` of
  `page.url.hash` picks the item. On desktop the drawer opens at
  `placement="end"`; on narrow screens it opens at `placement="bottom"`,
  switched through `matchMedia`. The drawer shows:
  - the title, a status badge (`wa-badge`) and the summary;
  - the notes as bullets;
  - twigs, each with its status;
  - "Needs" (dependencies) and "Unlocks" (the reverse dependencies), each as
    `#id` links, which opens a Civ-style prerequisite trail;
  - the parent branch, and the `shippedOn` date for a shipped item.

  Closing the drawer clears the hash with `replaceState(resolve('/(public)/roadmap'), {})`
  from `$app/navigation`, which keeps the GritQL resolve rule happy.
  Hash changes do not re-run any load, since the page has none.
- **Register `wa-drawer`** in `src/lib/webawesome.ts`. Its import path has to
  be checked against the installed Web Awesome build. Per invariant 11, no
  `undefined` is passed to a boolean `open`.

### Landing page teaser: `src/lib/components/roadmap/RoadmapHighlights.svelte`, used in `src/routes/(public)/+page.svelte`

- The section goes after `.cta`, with an `h2` "What's growing". It has two
  parts:
  - **Coming up:** a responsive grid of about 6 icon tiles from
    `featuredUpcoming(6)`. Each tile has an icon, a title and a status chip,
    and links to `resolve('/(public)/roadmap') + '#id'`.
  - **Recently added:** a list of `recentlyShipped(4)`, each item with a
    month-and-year date and a link to its node.

  Under both sits the link "See the full roadmap".
- No two of these links may share an accessible name, and the tiles must not
  duplicate the Recently added titles. Featured items are never shipped, so
  that is guaranteed.
- There are three landing-specific checks, set out in `docs/page-effects.md`:
  1. The VFX canvas must not swallow clicks: confirm it has
     `pointer-events: none`.
  2. The snapshot has to recapture when the body grows. A body
     `ResizeObserver` already handles this.
  3. The CTA's `margin-block-end: 50vw` has to be reduced, so the teaser
     follows it at a sensible gap and doesn't sit a screen away.

  The section is styled with the page's centred, amber look.

## Tests

- **Node:** `src/lib/roadmap/roadmap.test.ts`.
  - The real JSON parses.
  - The ids are unique, and every `dependsOn` resolves.
  - There are no cycles.
  - The `shipped` / `shippedOn` rule holds.
  - The selectors order and limit correctly.
  - Hand-made invalid fixtures are rejected, one per rule.

    text, and the filter toggles `aria-pressed` and dims the items that don't
    match.

    that the hrefs carry `#id`, and that link names are unique.
